### 题：584 寻找用户推荐人

- **我的答案**：WHERE referee_id = 2 OR referee_id IS NULL
- **错因**：A 读题错 —— 题目写「id != 2」，我写成「= 2」，`!` 丢了
- **卡在哪一句**：「被任何 id != 2 的用户推荐」这句，我读成了「被 id=2 推荐」
- **正解的关键一步**：条件应该是"排除 2"，不是"只要 2"；另外 NULL 行要单独 OR 回来
- **一句话重述**：`NOT (x = 2)` 不等于 `x <> 2 OR x IS NULL` —— NULL 永远要单独处理

### 题：1683 无效的推文

- **我的答案**：WHERE content > 15
- **错因**：E —— 不知道有 CHAR_LENGTH，也不懂"字符串 vs 数字"会自动转换
- **卡在哪一句**："字符数大于 15"，我以为 content > 15 就是比长度
- **正解的关键一步**：长度要用 CHAR_LENGTH(content) 取，content 本身是文本
- **一句话重述**：varchar 和数字比较时，MySQL 把文本转成数字（非数字开头 = 0），
  所以"比字符串"永远查不到东西；要比长度就用 CHAR_LENGTH / LENGTH

### 题：1378 使用唯一标识码替换员工ID

- **我的答案**：FROM EmployeeUNI LEFT JOIN EmployeeUNI ON unique_id = Employees.id
- **错因**：C —— JOIN 方向错（主表选反）+ 连接键写错 + 同表未起别名
- **卡在哪一句**："每位"用户的 unique_id，"没有的用 null 填充" —— 这两句就是在说"以员工表为主"
- **正解的关键一步**：FROM Employees LEFT JOIN EmployeeUNI ON u.id = e.id
- **一句话重述**：题目说"每位 X"就用 X 做 FROM；说"没有的填 null"就是 LEFT JOIN；
  连接键只认 `id = id`，`unique_id` 是**要显示的列**，不参与连接

### 题：1581 进店却未进行过交易的顾客

- **我的答案**：（没写出来，卡在"怎么连起来"）
- **错因**：B —— 知道 ON 和判 NULL，但不知道 JOIN / WHERE / GROUP BY 的先后
- **卡在哪一句**："只光顾不交易的次数" —— 不知道"次数"要用 GROUP BY 数

### 题：1661 每台机器的进程平均运行时间

- **我的答案**：（思路对，但没落成 SQL）
- **错因**：B —— 没意识到 start 和 end 在两行，需要"先合行"
- **卡在哪一句**："进程的用时 = end 减 start"，但这两列不在同一行
- **正解的关键一步**：自连接（同一 machine_id + process_id，一个 start 一个 end）
  连完每个进程一行，直接 AVG；或条件聚合 CASE WHEN end THEN +ts ELSE -ts
- **一句话重述**：一行 ≠ 一个业务单位时，先想办法合行（自连接 / 条件聚合）再聚合；
  进程数是 COUNT(DISTINCT process_id)，不是 COUNT(*)

### 题：1280 学生们参加各科测试的次数

- **我的答案**：FROM Examinations LEFT JOIN Students / Subjects（且 SELECT 多了逗号）
- **错因**：B —— 主表选错；没意识到要"先造 学生×科目 的全组合"
- **卡在哪一句**："每个学生参加每一门科目的次数" —— 这句话等于要求"没考过的也要显示 0"
- **正解的关键一步**：Students CROSS JOIN Subjects 造全组合，再 LEFT JOIN Examinations（两个条件都放 ON）
- **一句话重述**：题目要"每个 A × 每个 B"时，先从两张表 CROSS JOIN 造组合再挂事实表；
  LEFT JOIN 的条件放 ON 不放 WHERE；数次数用 COUNT(事实表列) 不用 COUNT(*)

  ### 题：1934 确认率

- **我的答案**：FROM Confirmations c LEFT JOIN Signups s，想用 c1/c2 两个别名分 confirmed/timeout
- **错因**：B —— 工具选重了。同一字段两种取值只需条件聚合，不需要自连接
- **卡在哪一句**："confirmed 的数量除以总数" —— 我以为要把两类拆成两张表才数得出
- **正解的关键一步**：主表 Signups（所有用户都要出现）LEFT JOIN Confirmations，

  自连接只用于"要看另一行的列"，而且连两次同一张表会行数爆炸（要 DISTINCT）

### 题：1251 平均售价

- **我的答案**：ROUND(AVG(b.timestamp - a.timestamp)) FROM UnitsSold LEFT JOIN Prices ON product_id
- **错因**：B —— 直接复用了上一题的表达式；且把"平均售价"当成了 AVG(price)
- **卡在哪一句**："平均售价" —— 我以为是价格的平均，其实是"总收入÷总销量"
- **正解的关键一步**：SUM(units*price)/SUM(units)，日期区间条件放 ON，IFNULL 兜 0
- **一句话重述**：加权平均 = SUM(值×权重)/SUM(权重)，AVG 只适用于"每行等权"；
  按日期取价用 BETWEEN 放在 ON 里（放 WHERE 会丢没卖出的产品）

### 题：1633 各赛事的用户注册率

- **我的答案**：LEFT JOIN Users 后 ROUND(COUNT(r.contest_id)/COUNT(u.user_id)*100, 2)
- **错因**：B —— 分母用"组内行数"，而分母应该是"全站用户总数"
- **卡在哪一句**："各赛事的注册百分率" —— 我没想清楚分母是谁
- **正解的关键一步**：分母 = (SELECT COUNT(*) FROM Users)，与分组无关

  全站级的分母用标量子查询，JOIN 后数不出来（JOIN 会把"没参与的行"过滤掉）

### 题：1211 查询结果的质量和占比

- **我的答案**：ROUND((SELECT COUNT(q.rating <= 3) FROM Queries)/COUNT(*)*100, 2)
- **错因**：E + A —— 不知道 COUNT(布尔) 会数全部行；且把"小于 3"写成了"<= 3"
- **卡在哪一句**："评分小于 3" 我读成了小于等于 3；"占比"我想在 COUNT 里写条件
- **正解的关键一步**：SUM(rating < 3) / COUNT(*) * 100，同一分组内直接算，不要子查询

  或 COUNT(CASE WHEN 条件 THEN 1 END)

### 题：1174 即时食物配送 II

- **我的想法**：想把分母换成"查有几个用户"的子查询
- **错因**：B —— 盯着分母，但真正的问题是"分子还在全部订单里算"
- **卡在哪一句**："即时订单在所有用户的首次订单中的比例" —— 我没先筛出"首次订单"
- **正解的关键一步**：WHERE (customer_id, order_date) IN (SELECT customer_id, MIN(order_date) GROUP BY customer_id)
  筛完首次订单后，COUNT(*) 天然就是用户数
- **一句话重述**：分子分母必须在同一批行里；
  "每组取最早/最新那条"用 (分组键, 极值) 元组 IN，只按极值会串人

### 题：550 游戏玩法分析 IV

- **我的想法**：COUNT(*)>1 判断登录多次 → 再看 device_id 是否相同 → 除以总玩家数
- **错因**：B —— 把"日期关系"当成了"次数关系"；还带进了无关字段 device_id
- **卡在哪一句**："首次登录的第二天再次登录" —— 我没锚定"首次登录是哪天"
- **正解的关键一步**：(player_id, event_date) IN (SELECT player_id, DATE_ADD(MIN(event_date), INTERVAL 1 DAY) ...)
  分母用 (SELECT COUNT(DISTINCT player_id) FROM Activity)
- **一句话重述**："第 N 天又来了"这类题，先算出"每个键的应该来的那天"，再用元组 IN 去匹配；
  次数 > 1 判不出日期关系

### 题：1084 销售分析 III

- **我的答案**：LEFT JOIN Sales ... WHERE s.sale_date BETWEEN 起 AND 止
- **错因**：B —— 把"仅在"（∀）当成了"有过"（∃）
- **卡在哪一句**："仅在 2019 年春季才售出的产品" —— 我只拦住了"区间内"，没排除"区间外"
- **正解的关键一步**：JOIN + GROUP BY + HAVING MIN(sale_date) >= 起 AND MAX(sale_date) <= 止
- **一句话重述**：SQL 没有"全部"这个词，
  要么反选（NOT EXISTS 排除反例），要么用极值（MIN/MAX 全落在范围内）
