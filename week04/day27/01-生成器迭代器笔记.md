## 一、迭代器协议

### 1.1 `for` 背后的三步（iter / next / StopIteration）

| 动作 | 背后调用的 | 谁来提供 |
| --- | --- | --- |
| iter(obj) | `obj.__iter__()` | 返回一个迭代器 |
| next(it) | `it.__next__()` | 返回下一个值 |
| 结束 | 抛 StopIteration | for 捕获后安静退出 |

### 1.2 可迭代对象 vs 迭代器（各举两个例子）

- 可迭代对象：list、str、dict
- 迭代器：iter([1, 2])、生成器、csv

### 1.3 我写的 CountDown（贴代码 + 输出）

**输入：**

```py
class CountDown:
    """自己实现的迭代器:3 2 1"""

    def __init__(self, start):    # 定义迭代器的初始化方法
        self.n = start            # 定义迭代器的状态

    def __iter__(self):            # 定义迭代器的迭代方法
        return self                 # 迭代器返回自己

    def __next__(self):           # 定义迭代器的下一个元素方法
        if self.n <= 0:
            raise StopIteration     # ← 用异常表示"没了"
        #self.n -= 1
        self.n = self.n - 1
        return self.n + 1

for x in CountDown(3):
    print(x)
```

**输出：**

```text
3
2
1
```

### 1.4 迭代器只能遍历一次（贴 `[]` 那次输出）

**输入：**

```py
nums = iter([1, 2, 3])
print("第一次：", list(nums))     # [1, 2, 3]
print("第二次：", list(nums))     # []   ← 空的！
```

**输出：**

```text
第一次： [1, 2, 3]
第二次： []
```

### 1.5 这个坑会咬人的场景（举一个）

```py
rows = csv.DictReader(f)
count = len(list(rows))      # 数一遍 → 迭代器被耗光了
for row in rows:             # 再遍历 → 一行都没有！
```

- 和 `@retry` 组合：重试时迭代器已经被耗掉一部分或全部，**第二次开始会静默地少处理或不处理**（不报错，最危险）
  - 迭代器作参数 → 重试时只剩剩下的；再调一次就是空
  - 修法：把迭代器**在函数内部新建**，或者直接传列表

### 2.4 `counter()` 连取 3 次得到 1 2 3

**输入：**

```py
def counter():
    n = 0
    while True:
        n += 1
        yield n


c = counter()
print("取第一次：", next(c))
print("取第二次：", next(c))
print("取第三次：", next(c))
```

**输出：**

```text
取第一次： 1
取第二次： 2
取第三次： 3
```

- n随着生成器被保存下来，每一次取出都是建立在上一步的基础上

### 2.6 生成器里 try/finally + close() 的输出

**输入：**

```py
def read_lines():
    print("  打开资源")
    try:
        yield "第一行"
        yield "第二行"
    finally:
        print("  释放资源")        # ← 一定会执行


g = read_lines()
print(next(g))          # 打开资源 / 第一行
print(next(g))          # 第二行
print("--- 不玩了 ---")
g.close()               # 释放资源        ← 显式关闭，finally 会跑
```

**输出：**

```text
  打开资源
第一行
第二行
--- 不玩了 ---
  释放资源
```

## 三、推导式

### 3.1 四种括号的对照表

| 括号 | 结果 | 什么时候算 |
| --- | --- | --- |
| [...] | list | 立刻造好整个列表 |
| {k: v ...} | dict | 立刻 |
| {x ...} | set | 立刻 |
| (...) | 生成器 | 惰性，用到才算 |

### 3.2 两种 `if` 位置（过滤 vs 选择）

| 写法 | if 在哪 | 含义 |
| --- | --- | --- |
| [n for n in nums if 条件] | 最后 | 过滤（不要的行直接跳过） |
| [A if 条件 else B for n in nums] | 前面 | 选择（每行都产出一个，二选一） |

- 看到 if 在 for 后面 → 过滤；在 for 前面 → 三元表达式。两者可以同时出现。同时出现时应该是先过滤再选择

### 3.3 嵌套两层的展开

**嵌套：**

```py
pairs = [(a, b) for a in [1, 2] for b in ["x", "y"]]
print(pairs)     # [(1, 'x'), (1, 'y'), (2, 'x'), (2, 'y')]
```

**展开：**

```py
pairs = []
for a in [1, 2]:
    for b in ["x", "y"]:
        pairs.append((a, b))
```

### 3.4 列表 vs 生成器的内存对比（贴 getsizeof）

| 方面 | 列表推导式 | 生成器表达式 |
| --- | --- | --- |
| 内存 | 全部装进去（随 n 增长） | 几乎不变（只存状态） |
| 能 len() 吗 | ✅ | ❌ |
| 能索引 [0] 吗 | ✅ | ❌ |
| 能遍历几次 | 无数次 | 一次 |

**输入：**

```py
import sys

lst = [n * n for n in range(1000000)]
gen = (n * n for n in range(1000000))

print("列表大小：", sys.getsizeof(lst), "字节")     # 约 800 万字节
print("生成器大小：", sys.getsizeof(gen), "字节")   # 约 200 字节
```

**输出：**

```text
列表大小： 8448728 字节
生成器大小： 200 字节
```

### 3.5 我以后什么时候不用推导式

| 不要用推导式的情况 | 为什么 |
| --- | --- |
| 里面有副作用（print、发请求、写文件） | 推导式应该只用来"造数据" |
| 三层以上嵌套 | 没人读得懂 |
| 逻辑超过"一个表达式" | 用普通 for |

## 四、大文件流式处理

### 4.1 readlines() vs for line in f

- readlines()：把每一行都变成一个字符串，装进一个列表。10 万行大约几十 MB；1000 万行就爆了。
- for line in f：文件对象自带 `__iter__` / `__next__` —— 它就是个迭代器。一行一行拿，用完就丢，不占用内存

| 写法 | 内存 | 能重复遍历 |
| --- | --- | --- |
| f.readlines() | 随文件大小增长 | ✅ |
| for line in f | 几乎不变 | ❌（一次） |
| list(f) | 跟 readlines() 一样 | ✅ |

### 4.2 我的生成器管道（贴三段）

```py
def iter_rows(path):
    """逐行产出 dict(不把整个文件读进内存)"""
    with open(path, encoding="utf-8") as f:
        for row in csv.DictReader(f):
            yield row
```

```py
def only_expected(rows, expected):
    """过滤：只留下 expected 等于指定值的行"""
    for r in rows:
        if r["expected"] == expected:
            yield r
```

```py
def pick(rows, key):
    """变形：只取某一列"""
    for r in rows:
        yield r[key]
```

### 4.3 怎么证明它是"惰性"的

**输入：**

```py
    print("① 造管道之前")
    pipeline = pick(only_expected(iter_rows(path), "200"), "userId")
    print("② 管道造好了，类型是：", type(pipeline).__name__)
    print("③ 现在才 list()")
    print("结果：", list(pipeline))
```

**输出：**

```text
① 造管道之前
② 管道造好了，类型是： generator
③ 现在才 list()
读了： 1
读了： 2
读了： 999
结果： ['1', '2', '999']
```

- 所有`"读了"`都在②和③之后，说明造管道的时候一行都没读。
