## 四、踩过的坑（最值钱的一节）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | Remote-SSH EPERM C:\ProgramData\ssh\ssh_config | 文件不存在，且该目录不允许非管理员写 | 管理员建空文件 + 授权读，或改用 ~/.ssh/config |
| 2 | Remote-SSH 卡“正在打开远程”（残留锁） | ~/.vscode-server 里的残留锁 + 死进程 | 删 `.locks` 和 `*.staging-*`，重连 |
| 3 | mysql < file.sql 报 1064 + 中文乱码、换行被吃 | 文件 UTF-8，客户端 character_set_client 是 GBK | 文件首行 SET NAMES utf8mb4; |
| 4 | 修完编码，输出还是乱码 | 服务器返回 UTF-8，终端按 GBK 解释 | 输出重定向到文件用 VS Code 看，或加 --default-character-set=utf8mb4 |
| 5 | curl -w 状态码拼成 404000 | -w 在超时前已输出，\|\| echo 000 又追加 | 先取 code="${raw:0:3}"，再校验是否三位数字 |
| 6 | AUTO_INCREMENT=17 但只有 5 行 | 被拒/回滚的插入也会消耗自增值 | 正常现象，id 只保证唯一不保证连续 |
| 7 | ss -tlnp 显示 8080 有个 python3 | 原来是 10/27 遗留的 http.server 孤儿进程（PPID=1） | 见下方「附：排查一个不明进程」 |

**附：排查一个不明进程（四步）**

```bash
# ① 找 PID 和进程名
ss -tlnp 'sport = :8080'
# → users:(("python3",pid=28888,fd=3))    记住这个 28888

# ② 看它的完整启动命令
ps -fp 28888
cat /proc/28888/cmdline | tr '\0' ' '; echo
# → python3 -m http.server 8080 --bind 127.0.0.1

# ③ 看它属不属于 systemd 服务
systemctl status 28888 | head -6
# → 显示 session-365.scope (transient) → 不是 service，可直接 kill

# ④ 关掉
kill -TERM 28888
sleep 2
ss -tlnp 'sport = :8080' || echo "✅ 端口已释放"
```

> **判据**：`systemctl status` 显示 `xxx.service` → 用 `systemctl stop`；
> 显示 `session-xxx.scope` → 用 `kill -TERM`。
> **别用 `pkill -f`** —— 会误杀同名的其他进程（曾把 SSH 会话自己干掉）。
