## 二、今天想清的概念

### 2.1 接口 vs URL

- **URL 是地址，接口是约定**
- 接口 = 方法 + 路径 + 参数规范 + 请求头 + **响应结构** + **状态码语义** + 错误约定
- 请求里只有前四项，**响应侧不在请求里**

### 2.2 请求 vs 接口 vs 用例

| 层 | 是什么 |
|---|---|
| 接口（契约） | 文档里那段约定 |
| 端点 | 方法 + 路径 |
| 请求 | 端点 + 这一次的具体参数 |
| 用例 | 请求 + 断言 |

**我的集合：8 个端点 / 11 条请求（用例）** —— 01 和 02 是同一个端点的两面。

### 2.3 接口测试的完整定义

> 按约定调用接口，验证：① 响应符不符合约定 ② **副作用**符不符合业务预期。
> 文档不清时，先抓包还原约定。

**httpbin 的局限**：只有响应，没有副作用/幂等/权限 → 这是我 README 里"已知限制"的本质。

### 3.2 术语一致性

| 说法 | 正确 | 常见错误 |
| --- | --- | --- |
| 集合变量 vs 环境变量 | 集合变量随集合走（导出带 initial），环境变量随环境走 | 把 uid 说成"环境变量"（它是 pm.collectionVariables） |
| Tunnel to vs GET | Tunnel = 只转发未解密；有 GET = 解密生效 | 把"只有 Tunnel"说成"没抓到" |
| initial vs current | initial = 导出/别人看到的；current = 只在本机 | 以为"我这里有值"就等于"文件里有值" |

**验证有没有把集合变量写成环境变量：**

```bash
grep -rn "环境变量" week03/day2*/01-*.md | grep -i "uid"
```

**输出：**

```text
0行，没有输出。
```

- 表示没有把集合变量写成环境变量
