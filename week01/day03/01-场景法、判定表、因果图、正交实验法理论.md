# Day 3 ｜ 场景法、判定表、因果图、正交实验法

> 日期：2026-10-21

## 1. 理论要点

### 1.1 方法选择对照表

| 需求长什么样 | 用哪个方法 | 举例 |
| --- | --- | --- |
| 输入是一个取值范围 | 等价类 + 边界值 | 年龄在1–120之间 |
| 多个条件组合决定结果 | 判定表 | 商场促销 |
| 有明确的业务流程/状态流转 | 场景法 | 登录下单 |
| 参数组合爆炸（多参数各自多种取值） | 正交法 | "浏览器 × 系统 × 分辨率" |
| 以上都不适用 / 需要补充 | 错误推测法 |

### 1.2 基本流和备选流分别是什么？一条"场景"由什么组成？

- 基本流指的是一切顺利的主流程
- 备选流指的是主流程上的分支、异常、回退
- 一条“场景”由一条基本流和数个备选流组成
- 一条场景派生出一条用例

### 1.3 判定表的四个组成部分分别叫什么、在哪？

- 条件桩，在左上，列出所有条件
- 动作桩，在左下，列出所有可能的动作
- 条件项，在右上，每个条件在规则下的取值（是/否/具体的值）
- 动作项，在右下，每条规则对应的结果

### 1.4 n 个条件会产生多少条规则？什么时候需要化简？

- **规则数 = 各条件"取值数"相乘**
- 只有当 n 个条件**全都是布尔值（Y/N）且互不相关**时，才退化成 2ⁿ
- 全布尔：3 个条件 → 2³ = 8 条
- 多值：等级(3) × 金额(3) × 促销(2) = **18 条**
- 5 个条件 → 32 条规则  ← 这时候必须化简

### 1.5 什么是"无关条件"？化简时怎么表示？

- 无关条件指的是某个条件的取值不影响结果
- 化简时用 —（无关）表示

### 1.6 L9(3⁴) 三个数字分别代表什么？

- 9代表需要的试验总次数
- 4代表因子，也就是参数
- 3代表水平，也就是参数的取值

### 1.7 正交法为什么能减少用例？代价是什么？

- 绝大多数缺陷由 1–2 个参数的交互触发，3 个以上参数同时交互才出问题的概率极低。所以不用测全组合。
- 正交法不保证三个以上因子的组合被覆盖。所以它适合"参数多、组合爆炸、但风险相对均匀"的场景。
- 正交表保证：任意两个因子的所有水平组合，都至少出现一次。 这叫 pairwise 覆盖（两两组合覆盖）。

### 1.8 给你一个"电商满减活动"，你选哪个方法？为什么？

- 我会选择使用判定表
- 电商满减是多个条件组合决定结果，例如满减+优惠劵+会员=最终价格

### 1.9 给你一个"商品列表支持按价格/销量/上架时间排序，且有 3 种排序方向"，你选哪个方法？

- 我选择正交法
- 因为有多参数各自多种取值
- 不过 3×3 = 9 种全测也就 9 条，正交压缩不了，所以先枚举更合适

### 1.10 因果图 5 个约束 + 与判定表的关系

| 约束 | 符号 | 含义 |
| --- | --- | --- |
| 互斥 | E | 最多一个成立（不能同时） |
| 包含 | I | 至少一个成立 |
| 唯一 | O | 有且仅有一个成立 |
| 要求 | R | A 成立则 B 必须成立 |
| 屏蔽 | M | A 成立则 B 不成立 |

- 因果图的实际用法是"因果图 → 判定表 → 用例"，它本身很少直接产出用例，所以实际工作中用得少，重点是理解它和判定表的关系。

## 方法选择

| 参数组合总数 | 建议 |
| --- | --- |
| ≤ 12 种 | 直接全测，别用正交 |
| 13–30 种 | 可以考虑正交 |
| > 30 种 | 正交法收益明显（尤其参数 ≥ 3 个时） |
