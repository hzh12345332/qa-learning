## BUG-003 ｜ Last Name 的输入被写入 First Name，导致无法完成结算（problem_user）

| 字段 | 内容 |
| --- | --- |
| 缺陷编号 | BUG-003 |
| 所属模块 | SauceDemo结算 |
| 环境 | 操作系统Windows 11 家庭中文版 25H2 ｜ Edge 154.0.4258.37 ｜ 1920×1080 |
| 发现版本 | saucedemo.com 线上版（2026-10-22 复测） |
| 前置条件 | 使用**problem_user / secret_sauce**进入结算页面 |
| 严重程度 | 致命  |
| 优先级 | P0  |
| 状态 | 新建 |
| 提交人 / 日期 | 侯振昊  2026-10-22 |

**复现步骤**

1. 打开 https://www.saucedemo.com/ ，Username 输入 `problem_user`，Password 输入 `secret_sauce`，点击 `LOGIN`
2. 在商品列表点击任一商品的 `Add to cart`
3. 点击右上角购物车图标，进入购物车页
4. 点击 `CHECKOUT`
5. First Name 填 `Test`，Last Name 填 `a`，Zip 填 `518000`
6. 点击 `CONTINUE`

**预期结果**

a 应显示在 Last Name 输入框中，First Name 保持 Test 不变，然后跳转到 `Checkout: Overview` 订单概览页，正常显示商品条目与 Total

**实际结果**

1. 在 Last Name 输入框输入 `a`，该字符**出现在 First Name 输入框**中，Last Name 仍为空、边框变红
2. 再次点击 Last Name 输入，First Name 的值被覆盖为新的内容，**Last Name 始终为空**
3. 点击 `Continue`，页面下方出现红色提示 `Error: Last Name is required`，停留在当前页
4. 重复步骤 1–3 均无法通过，**结算流程被完全阻断，无任何绕过方式**

**附件**

- 页面截图（文字描述）：页面显示 First Name = `a`，Last Name 为空且红色边框，底部红色错误条 `Error: Last Name is required`，右上角购物车角标为 1

**判定理由**

- **Severity = 致命**：
  核心功能（下单）完全不可用，且无绕过方式。
  机制是输入内容被路由到错误字段，导致必填项永远无法填入，
  形成"填了还是空 → 报必填 → 还是填不进去"的死循环。
  排除"严重"的理由：严重指"有替代方案"，而这里用户**无论如何都下不了单**。
- **Priority = P0**：阻断 problem_user 的全部下单流程，必须当日修复。

## BUG-001 ｜ 切换排序方式后列表页价格显示错误，但详情页/购物车/结算页价格正确（不影响实付金额）（visual_user）

| 字段 | 内容 |
| --- | --- |
| 缺陷编号 | BUG-001 |
| 所属模块 | SauceDemo商品列表 / 排序 |
| 环境 | 操作系统Windows 11 家庭中文版 25H2 ｜ Edge 154.0.4258.37 ｜ 1920×1080 |
| 发现版本 | saucedemo.com 线上版（2026-10-22 复测） |
| 前置条件 | 使用**visual_user / secret_sauce**进入商品列表 |
| 严重程度 | 严重 |
| 优先级 | P0  |
| 状态 | 新建 |
| 提交人 / 日期 | 侯振昊  2026-10-22 |

**复现步骤**

1. 打开 https://www.saucedemo.com/ ，Username 输入 `visual_user`，Password 输入 `secret_sauce`，点击 `LOGIN`
2. 在商品列表点击右上角的排序下拉框
3. 选择 `Name（Z to A）`

**预期结果**

1. 选择 `Name (Z to A)` 后，商品顺序正确变为 Z→A，**但各商品的显示价格同时发生了变化**，与排序前不一致
2. 再次切换排序方式，价格再次变化，且无规律
3. 进入商品详情页，价格显示正确
4. 进入购物车页，价格显示正确
5. 进入结算页，Total 计算正确（与详情页价格一致）

**实际结果**

1. 在点击商品列表点击右上角的排序下拉框并选择`Name（Z to A）`后，商品顺序和价格都发生变化
2. 再次切换排序方式，价格再次变化且无规律；商品顺序仍正确
3. 点击 商品链接进入商品详情页可以看到正确价格
4. 进入购物车看到的价格和最终结算价格也都为正常价格
5. 重复步骤 1–4 均为同样结果

**附件**

- 页面截图（文字描述）：商品列表展示的价格随着点击排序按钮随机变化

**判定理由**

- **Severity = 严重**：
  核心功能（下单）可用，且有绕过方式。
  商品列表价格混乱，商品详情页和购物车的价格正常
- **Priority = P0**：削减用户的信任和购买欲望，必须当日修复。

2. 在商品列表点击任一商品的 `Add to cart`

6. 点击 `CONTINUE`

**预期结果**

点击 `Continue`，页面下方出现红色提示 `Error: Last Name is required`，停留在当前页

**实际结果**

  不判"致命"的理由：不涉及资金损失，也不导致流程崩溃。
- **Priority = P1**：脏数据进库，但需要用户主动留空才触发，必须本迭代内修复。
