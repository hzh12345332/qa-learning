## 一、函数是一等公民

### 1.1 `run_case` 和 `run_case()` 的区别（贴两种写法的输出）

| 写法 | 拿到什么 | 类型 |
| --- | --- | --- |
| run_case | 函数本身 | <class 'function'> |
| run_case() | 函数的返回值（这里是 "PASS"） | <class 'str'> |

**输入：**

```py
def run_case():
    return "PASS"

f = run_case         # f 是函数本身
print(f())           # → PASS        （加括号才执行）

g = run_case()       # g 是返回值，也就是字符串 "PASS"
print(g)             # → PASS        （g 本身就是结果，不用再加括号）
g()                  # → TypeError: 'str' object is not callable
```

**run_case 输出：**

```text
PASS
```

**run_case() 输出：**

```text
TypeError: 'str' object is not callable
```

### 1.2 `def` 是赋值语句：我怎么证明的（贴 `type(run_case)`）

**输入：**

```py
def run_case():
    return "PASS"
print(run_case)          # <function run_case at 0x000001F...>
print(type(run_case))    # <class 'function'>
```

**输出：**

```text
<function run_case at 0x000001531F36CA40>
<class 'function'>
```

### 1.3 四种用法：赋值 / 传参 / 返回 / 放容器（各贴一行代码）

**赋值：**

```py
a = run_case          # a 指向同一个函数对象（没加括号）
print(a is run_case)  # → True
```

**传参：**

```py
def run_all(cases, on_result):
    for c in cases:              # c 是函数
        r = c()                  # 这才执行
        on_result(c.__name__, r)


run_all([run_case, run_case2], lambda n, r: print(n, "→", r))
```

**返回：**

```py
def make_runner(case):
    def wrapper():
        print("开始：", case.__name__)
        return case()
    return wrapper            # ← 返回的是函数，不是它的结果


wrapped = make_runner(run_case)
wrapped()
```

**放容器：**

```py
REGISTRY = {"ok": run_case, "login": run_case}
REGISTRY["ok"]()
```

### 1.4 函数有哪些属性（贴 `__name__`、`__doc__`）

```py
def run_case():
    """一个测试函数"""
    return "PASS"
print(run_case.__name__)     # run_case
print(run_case.__doc__)      # 一个测试函数
print(run_case.__module__)   # __main__
print(run_case.__dict__)     # {}
```

## 二、闭包

### 2.1 闭包的三个条件（用自己的话写）

1. 有外层函数
2. 内层函数引用了外层函数变量
3. 外层返回内层函数

**例如：**

```py
def test():
    a = 1
    def test1():
        print(a)
    return test1
```

### 2.2 `__closure__` 和 `cell_contents` 贴输出

**输入：**

```py
def test():
    a = 1
    def test1():
        print(a)
    return test1
b = test()

print(b.__code__.co_freevars)    #查看闭包变量
print(b.__closure__)    # 查看所有闭包格子（cell），值在cell_contents 里
print(b.__closure__[0].cell_contents)   #查看特定位置变量的值，从0开始数 
```

**`__closure__` 输出：**

```text
(<cell at 0x000002C81EE566E0: int object at 0x00007FFC134B49B8>,)
```

**`cell_contents` 输出：**

```text
1
```

### 2.3 非闭包长什么样（`None` 的那个例子）

**非闭包输入：**

```py
def outer():
    def inner():
        return 1          # 没引用外面的东西
    return inner


print(outer().__closure__)    # None
```

**输出：**

```text
None
```

### 2.4 `nonlocal` 不加报什么错（贴完整报错）

**输入：**

```py
def make_counter():
    count = 0

    def inner():
        count += 1     # ← 这里没有 nonlocal
        return count

    return inner


c = make_counter()
print(c(), c(), c())         # ← 不加 nonlocal：UnboundLocalError
                            #   加了 nonlocal 才是 1 2 3
```

**输出：**

```text
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

- 不加 `nonlocal` 会导致Python认为赋值的变量是函数体的局部变量，但是函数体里没有定义，所以报错。
- 加 `nonlocal` 的意思是：这个变量不是新增的，是外层的那个

### 2.5 late binding：`[2, 2, 2]` 的原因和两种修法

- 原因：取值发生在“调用那一刻”，取的是那一刻变量的值。 本例里所有调用都在循环之后，那时 i 已经是 2 —— 所以全是 2。

**修法一：**

- 默认参数 —— 默认值在"定义时"求值，等于当场存了一份，但是不再引用外层变量，所以不算是闭包了

```py
fs = [lambda i=i: i for i in range(3)]
print([f() for f in fs])       # [0, 1, 2]
```

**修法二：**

- functools.partial 把当前值绑进去

```py
from functools import partial
fs = [partial(lambda x: x, i) for i in range(3)]
print([f() for f in fs])       # [0, 1, 2]
```

**修法三：**

- 工厂函数

```py
def make_getter(v):
    def get():
        return v
    return get

fs = [make_getter(i) for i in range(3)]
print([f() for f in fs])                    # [0, 1, 2]
print(fs[0].__closure__[0].cell_contents)   # 0  ← 各自的格子，互不干扰
```

### 2.6 为什么 `info` 和 `err` 能记住不同的 prefix

- make_logger("INFO") 每调一次，就产生一个新的局部变量 prefix → 一个新的 cell。 info 和 err 各自持有一个 cell，所以各记各的。 和“修法三：工厂函数”是同一个机制。

```py
def timer(func):
```

### 3.4 `*args` / `**kwargs` 不加会报什么错（贴完整报错）

**不加 `*args` / `**kwargs` 输入：**

```py
def timer(func):
    def wrapper():

        result = func()
        cost = time.time() - start
        print("[timer] %s %.3fs" % (func.__name__, cost))
        return result
```


### 3.5 加不加 `@wraps` 的对比表（`__name__` / `__doc__`）

| 属性 | 不加 @wraps | 加了 |
| --- | --- | --- |
| `__name__` | wrapper | run_case |
| `__doc__` | None | 原文档字符串 |
| `__module__` | 装饰器所在模块 | 原函数模块 |
| `__qualname__` | `timer.<locals>.wrapper` | run_case |
| `__wrapped__` | 无 | 指回原函数（inspect.signature 靠它读参数） |

### 3.6 `start` 放外面 vs 放里面，耗时差多少（贴两次输出）

**前提：循环输出5次：**

```py
run_case = timer(run_case)
for _ in range(5):
    run_case()
```

**放在里面的输入：**

```py
def timer(func):    #定义函数timer，参数为func
    def wrapper():    #定义函数wrapper
        start = time.time()    # 记录开始时间
```

**放在里面的输出：**

```text
[timer] run_case 0.101s
[timer] run_case 0.101s
[timer] run_case 0.101s
[timer] run_case 0.100s
[timer] run_case 0.100s
```

**放在外面的输入：**

```py
def timer(func):    #定义函数timer，参数为func
    start = time.time()
    def wrapper():    #定义函数wrapper
```

**放在外面的输出：**

```text
[timer] run_case 0.113s
[timer] run_case 0.213s
[timer] run_case 0.314s
[timer] run_case 0.414s
[timer] run_case 0.515s
```

- start 在里面：0.101 0.101 0.101 0.100 0.100 —— 每次重新计时，差值≈0
- start 在外面：0.113 0.213 0.314 0.414 0.515 —— 起点固定，步长恒为单次真实耗时 0.1005
- 结论：误差 = 装饰时刻到调用时刻的间隔；首值比真实值多出的部分，就是那段间隔。

### 3.7 `@A @B def f` 展开成什么、执行顺序

- 展开成为：`f = A(B(f))`
- 包装顺序（由内向外）：先 B，再 A
- 执行顺序（调用时，由外向内）：先 A 的 wrapper → 再 B 的 wrapper → 最后原函数

## 四、给 report_class.py 加装饰器

### 4.1 decorators.py 全文

```py
import time
from functools import wraps


def timer(func):
    """打印函数耗时，并原样返回结果"""
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        try:
            return func(*args, **kwargs)
        finally:
            print("[timer] %s %.3fs" % (func.__name__, time.time() - start))
    return wrapper


def log_calls(func):
    """打印每次调用的函数名和参数"""
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("[call] %s args=%s kwargs=%s" % (func.__name__, args, kwargs))
        return func(*args, **kwargs)
    return wrapper
```

### 4.4 为什么用 try/finally 而不是 except

- try / finally：耗时一定打印，而且异常照常往上抛（finally 不改变控制流）
- try / except：异常被吞掉 → 返回 None → 失败用例被当成通过
- 直接 print 在 return 后面：一抛异常这行就不执行，连记录都没有
- 装饰器可以加观测，不能改结果。
