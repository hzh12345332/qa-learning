## 一、DevTools Network

### 1.1 七列各看什么（贴关键几行）

| 列 | 中文 | 看什么 |
| --- | --- | --- |
| Name | 名称 | 请求的路径（/get、/api/user/1） |
| Status | 状态 | 200 / 302 / 404 / 500 —— Day 15 的状态码 |
| Type | 类型 | xhr / fetch（接口）、document（页面）、script / css / img |
| Initiator | 发起者 | 谁发的：某行 JS、某次跳转 |
| Size | 大小 | 响应体大小；(disk cache) = 走了缓存，没真发请求 |
| Time | 耗时 | 从发起到收完 |
| Waterfall | 瀑布图 | 各阶段耗时叠在一起，能看出卡在哪一段 |

### 1.2 一条请求的五个 tab（Headers / Payload / Response 各截一段）

**标头 Headers**

```text
请求 URL        https://httpbin.org/post
Request method  POST
Status code     200 OK
Remote address  ...
```

- General 那四行 = Day 15 的“起始行”：方法 + 路径 + 协议 + 状态码
- `Remote address` 是**服务器**的 IP，不是我本机的 —— 以后要注意区分

**载荷 Payload**

```text
{name: "test", age: 18}
age: 18
name: "test"
```

- JSON body 在这里，不在 Headers 里
- 判断依据：`Content-Type: application/json` → body 落在 Request Payload
- 如果是 GET，这里只有 Query String Parameters

**响应 Response**

```js
{ "json": { "name": "test", "age": 18 }, "url": "https://httpbin.org/post" }
```

- 服务器把我发的 body 原样回显在 `"json"` 字段里
- 这证明：**发出去的就是这个 body**，没被中间层改过

### 1.3 Preserve log 不勾会怎样（我的实测）

- Preserve log 不勾会导致跳转页面时请求列表直接清空，容易造成误判没发请求

### 1.4 一次 TTFB 分析：慢在哪一段

**TTFB输出**

```text
排队                0.57 ms
已停止              0.53 ms
已发送请求          0.24 ms
正在等待服务器响应  239.40 ms   ← 占 99%
Content download    0.35 ms
```

- 结论：慢在服务端处理/网络往返，不在响应体大小 —— 换分页、加压缩都没用。

    "a": "1",
    "b": "2"
  },

## 二、抓包原理

### 2.1 为什么能解密 HTTPS（画一个"两段加密"的图）

- 因为抓包工具把一条加密连接，"拆成"两条：

```text
浏览器  ═══加密═══►  抓包工具  ═══加密═══►  服务器
    （用工具自己签的证书）  （用服务器真的证书）
```

- 抓包工具在中间"解密 → 看 → 再加密" —— 这就是中间人（MITM，Man-in-the-Middle）。
- 所以它不是"破解"了 HTTPS，是"被授权的中间人"：浏览器/系统信任了工具的根证书，就等于同意了“这个中间人可以替服务器说话”。

### 2.2 根证书装在哪、为什么必须装

**根证书装在：**

```text
certmgr.msc  →  受信任的根证书颁发机构  →  证书
```

**没装根证书时：**

- 浏览器一看"这证书不是真服务器签的" → 报 `NET::ERR_CERT_AUTHORITY_INVALID` → 页面打不开。

- 装了之后：浏览器一看"这证书是「我信任的那个根」签的" → 放行。

### 2.3 抓不到的五类情况

| 情况 | 现象 | 原因 |
| --- | --- | --- |
| 没走代理 | 工具里一条都没有 | 客户端没配代理（curl 默认就不走系统代理） |
| 没装/没信任根证书 | 有 CONNECT，但内容是加密的 | 证书没装到"受信任的根"里 |
| HTTP/2、HTTP/3(QUIC) | 有的工具只看到一部分 | 协议差异；QUIC 走 UDP，普通 HTTP 代理接不住 |
| UWP / AppContainer 隔离 | 应用商店 App、部分 Edge 进程抓不到 | Windows 沙箱的 loopback 限制；用工具栏的 WinConfig 豁免 |
| 证书固定（SSL Pinning） | App 直接断连 | App 自己校验了服务器证书，中间人签的它不认 |

### 2.4 pinning 是什么，为什么不是我的锅

- pinning 是证书固定，App 自己校验了服务器证书，中间人签的它不认

## 三、Fiddler

### 3.1 抓到 httpbin 明文的证据（贴关键几行）

**Fiddler 列表里两条都在**（这是解密生效的关键）：

- `Tunnel to httpbin.org:443` —— CONNECT（只建隧道）
- `GET httpbin.org/get` —— 解密后的真实请求（200）

**点开 GET 那条 → Inspectors → 下半区 `JSON`**：

```json
{
  "args": {},
  "headers": { "Host": "httpbin.org" },
  "method": "GET",
  "url": "https://httpbin.org/get"
}
```

### 3.2 Filters 只抓一个域名

1. 点 Filters 标签
2. 勾 Use Filters
3. 第一个下拉保持 - No Zone Filter -；第二个下拉选 Show only the following Hosts；下面文本框填 httpbin.org
4. 点 Actions → Run Filterset now
效果：列表里只剩 httpbin 的请求。这是"在噪音里找信号"的基本功。

### 3.3 curl -x 的坑

- curl 默认不走系统代理。所以 Fiddler 开着，curl 的请求不会出现在列表里。
- 现象：只有 CONNECT，没有 GET。
- 原因：-s 把 SEC_E_UNTRUSTED_ROOT 吞了；Schannel 不认 Fiddler 的证书。
- 解决：-sS 看错误，-k 跳过验证。

**需要手动指定：**

```bash
curl -x http://127.0.0.1:8888 -sS "https://httpbin.org/get?a=1"
```

### 3.4 断点改了哪条请求的参数、结果如何

- 拦到的请求：`GET http://httpbin.org/get?a=1`
- 改了什么：URL 参数 `a=1` → `a=999`
- 结果：响应 JSON 里 `args.a` 变成 `999`，`url` 也变成 `?a=999`
- 说明：断点改的是**发出前**的请求，服务器收到的就是改后的值

**踩到的坑**：全局断点会先拦住 `CONNECT`（隧道建立），那一步没有业务参数可改。
要先 `Run to Completion` 放行隧道，才能拦到真正的 GET。

### 3.5 AutoResponder 替换了哪个响应

- 匹配规则：`httpbin.org/get` → 本地文件 `week03/day20/scripts/fake-user.json`
- 结果：浏览器显示的是**用户不存在**，不是 httpbin 返回的内容
- 说明：请求照常发出，但**响应在本地被替换**了，服务器完全不知情
- 结论：这跟 Day 19 的 Mock 是一回事 —— **控制返回，让“后端不可能给你的场景”变得可复现**

## 四、定位问题

### 4.1 六种情况对照表（自己默写一遍）

| 你看到的 | 结论 | 找谁 |
| --- | --- | --- |
| 列表里根本没有这条请求 | 前端没发（JS 报错、事件没绑、按钮被遮住） | 前端 |
| 请求发了，参数不对/缺字段 | 前端传参错 | 前端 |
| 请求发了，参数对，返回 4xx | 前端传了非法值 / 没带凭证 | 前端（或接口文档不清） |
| 请求发了，参数对，返回 5xx | 后端异常 | 后端 |
| 返回 200，但字段缺失/值不对 | 后端逻辑或数据 | 后端 |
| 返回 200，字段对，但页面显示错 | 前端渲染 | 前端 |

### 4.2 我实际演练的一次"没发 vs 失败"

1. 不勾 Preserve log，打开一个会在加载后跳转的页面后列表会清空，造成没有发送请求的误判
2. 勾 Preserve log，打开一个会在加载后跳转的页面后列表不会清空，依然保留上一个页面的请求记录

### 4.3 把抓到的请求导入 Postman（贴关键几行）

- **来源**：`https://api.github.com/users/octocat`（GET，Type: fetch）
- **导入方式**：DevTools 右键 → `Copy as cURL (bash)` → Postman `Import` → `Raw text` → 粘贴
- **导入后改造**：
  - 删掉 `User-Agent`、`Accept-Encoding` 这些浏览器专属头（Postman 会自己加）
  - 加断言：状态码 200 + `pm.expect(pm.response.json().login).to.eql('octocat')`
- **结果**：发一次 200，响应里有 `login`、`id`、`public_repos` 等字段
- **坑**：接口有缓存导致第二次开始，状态码显示304。
- **解法**：删掉 If-None-Match / If-Modified-Since

## 五、手机抓包

### 5.1 代理配置

```text
手机  ──WiFi代理──►  我的电脑（Fiddler:8888）  ──►  互联网
```

### 5.2 证书安装

1. 手机浏览器访问 http://<电脑IP>:8888 → 下载 Fiddler 根证书
2. 设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书
3. 选下载的 .cer 文件

- 端口从 8080 改 8888 才通
- 装了证书（HarmonyOS 路径）
- 实测：手机访问 `http://192.168.x.x:8888` 出现 Echo Service 页面 = 代理通
- 装证书后抓到 httpbin.org/get 明文（UA: HuaweiBrowser），说明用户证书被浏览器信任
- 插曲：grs.dbankcloud.com 报证书链错误 —— 华为内部 CA 不在 Windows 信任列表，点 No 放弃该会话
- 结论：代理通 ≠ App 能抓，App 还要过 Android 7+/pinning 这关

### 5.3 Android 7+ 抓不到 App 的原因

- Android 7.0 起，App 默认只信任"系统证书"，不信任"用户安装的证书"。
