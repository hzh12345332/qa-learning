# Day 5 ｜ 测试计划（saucedemo）

> 练习要求：写一份一页测试计划，覆盖范围/策略/类型/环境/进度/进出入准则/风险

## 范围

需要测：登录与账号校验（含6类用户角色）；商品列表展示（图片、名称、描述、价格）；四种排序（A-Z / Z-A / 价格升 / 价格降）；购物车增删与角标计数；三步结算（收货信息 → 订单确认 → 下单完成）

不测：后端 API 性能与压力测试；安全渗透测试；多语言与支付网关集成；真实数据持久化验证（站点为练习环境，订单不产生真实交易）。

## 策略

1. 登录 ： 等价类 + 判定表 + 错误推测
2. 商品排序 ： 等价类
3. 购物车 ： 等价类
4. 结算表单 ： 判定表
5. 主链路 ： 场景法

## 类型

**需要做**

- 功能测试
- 回归测试
- 冒烟测试

**不需要做**

- 性能测试 ： 在这里做"性能测试"，结论既不可信也无处可比。
- 安全测试 ： SauceDemo 不具备真实业务系统的攻击面，代码与数据逻辑极简，在这里"发现"的安全问题迁移不到真实项目。

## 环境

| 维度 | 配置 |
| --- | --- |
| 应用 URL | https://www.saucedemo.com/ |
| 浏览器 | Edge |
| 视口 | 桌面 1440×900 |
| 测试账号 | standard_user / secret_sauce；其余五类角色使用对应内置账号 |
| 数据 | 无需预置后端数据；每次执行前通过侧边栏“Reset App State”恢复干净的购物车状态 |

## 进度


| 阶段 | 内容 | 预计 |
| --- | --- | --- |
| 冒烟 | 跑 11 条核心用例（见 `04-冒烟测试用例集.md`） | 0.5 天 |
| 第一轮功能测试 | 登录/列表/排序/购物车/结算 五模块 | 2 天 |
| 缺陷回归 | 修复验证 + 影响范围回归 | 1 天 |
| 全量回归 + 报告 | 主链路复跑、输出测试报告 | 0.5 天 |

## 进入与退出准则

**进入准则：**
SauceDemo 站点可访问且登录页正常渲染；六类测试账号均可用（密码统一为 `secret_sauce`，`locked_out_user` 预期被拒绝登录）；测试用例已评审通过

**退出准则：**

- 所有 P1 级缺陷已修复并回归通过，无 P0/P1 遗留缺陷
- 主链路在 standard_user 下 100% 通过
- 六类账号对照结果均已完成并记录偏差
- 测试总结报告已提交

## 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 站点是公开练习站，可能有其他人的环境或者操作导致状态不一致 | 用例失败原因难判定 | 每次执行前点 Reset App State 恢复干净状态并且提前确认自己的环境 |
| 六类账号的缺陷行为由站点预置，无法确认真实需求 | 判"这是缺陷"可能误判（实际是设计如此） | 判定前先对照 `standard_user` 的正常表现，确认偏差 |
| 无真实后端数据，无法验证持久化 | 数据层缺陷测不出来 | 在报告中明确"数据持久化不在本次范围" |
