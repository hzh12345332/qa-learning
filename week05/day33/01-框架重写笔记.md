## 一、旧的 105 行在干什么

### 1.1 六个职责

| 行 | 方法 | 它干的事 | pytest 版归谁 |
| --- | --- | --- | --- |
| 21–29 | load_config() | 文件在不在 → 读 JSON → 解析错误转 SystemExit | cfg fixture |
| 32–37 | _do_request() | 发 GET，套 retry 装饰器 | client + 请求那 3 行 |
| 39–56 | run_case() | 一条用例：请求 → 比 expected → 组装结果 dict | 一个 test_ 函数 |
| 58–64 | run_all() | 循环 CSV + with ApiClient(...) | 钩子自动展开 |
| 66–72 | write_report() | 把 results 写成 report.json | --junitxml |
| 74–77 | summary() | 数通过/失败，拼成一句话 | pytest 结尾行 |
| 79–84 | run() | 编排上面几步 | pytest 运行时 |
| 86–99 | main() | logging.basicConfig + 路径 + sys.exit | 全删 |

### 1.2 三行死代码

**输入：**

```py
sys.exit(1 if runner.run() else 0)     # ← 走到这里，进程直接结束
runner.run_all()                        # ← 死代码
runner.write_report()                   # ← 死代码
print(runner.summary())                 # ← 死代码
```

- sys.exit() 是立刻退出进程，它后面的三行永远不执行

### 1.3 两套装饰器：ApiClient.get 用的是哪一份

- `report_class.py` import 的是 `decorators.py` 那份
- 但 `api_client.py` 自己那份**不是死代码**：`ApiClient.get` 上的 `@retry` / `@timer` 就是它
  （实测 `ApiClient.get.__module__` → `api_client`）
- 后果：`_do_request` 套 3 次重试，`ApiClient.get` 内部又套 3 次 → **3×3 = 9 次请求**（实测 `run_all 21.675s`）

## 二、分层怎么切

### 2.1 四层各放哪（配置 / 连接 / 数据 / 用例）

| 层 | 放哪 | 为什么 |
| --- | --- | --- |
| 配置层 | conftest.py 的 cfg fixture | 路径/超时/baseUrl 会变，代码不变 |
| 连接层 | conftest.py 的 client fixture | Session 复用 + 自动关闭 |
| 数据层 | conftest.py 的 load_cases() + 钩子 | 加用例只改 CSV |
| 用例层 | test_*.py | 只写断言 |

### 2.2 判断分层的唯一标准：改一个东西动几个文件

- 改一个东西时，你要动几个文件？ 加一条用例 → 只动 CSV ✅｜加一个环境 → 只动 config ✅｜改断言 → 只动 test ✅

## 三、钩子：pytest_generate_tests

### 3.1 conftest.py 的数据层

**输入：**

```py
CONFIG_PATH = "week04/day23/data/config.json"
DATA_PATH = "week04/day23/data/users.csv"


def load_config(path):
    with open(path, encoding="utf-8") as f:
        return json.load(f)


@pytest.fixture(scope="session")
def cfg():
    """配置 → 从 config.json 读，不再硬编码"""
    return load_config(CONFIG_PATH)


@pytest.fixture(scope="session")
def client(cfg):
    s = requests.Session()
    yield s
    s.close()

@pytest.fixture
def only_in_sub():
    return "SUB_ONLY"

def load_cases(path):
    """读 CSV → 每行一个 dict(不是元组！)"""
    with open(path, encoding="utf-8", newline="") as f:
        rows = list(csv.DictReader(f))
    assert rows, "users.csv 里没有数据（路径错了？文件空了？）"
    return rows


# ---- 数据层：测试函数里出现 "row" 这个名字，就自动展开 ----
def pytest_generate_tests(metafunc):
    if "row" in metafunc.fixturenames:
        rows = load_cases(DATA_PATH)
        metafunc.parametrize("row", rows, ids=[r["userId"] for r in rows])
```

### 3.2 metafunc.fixturenames 是什么，为什么 "row" 是触发器

- `pytest_generate_tests` 是钩子（pytest 在**收集期**调用它）
- `metafunc.fixturenames` 是"当前这个测试函数需要的所有名字"的列表
- 钩子判断 `"row" in metafunc.fixturenames` → 成立就注入数据

### 3.5 为什么不 from conftest import

- 因为 `from conftest import` 靠 pytest 加载 conftest.py 时把模块注册进了 sys.modules["conftest"]，所以 from conftest import 正好命中缓存。
- 换一种结构就崩：多个层级各有 conftest.py 时，sys.modules["conftest"] 到底指向哪一个，取决于加载顺序。

| 方面 | from conftest import + parametrize | pytest_generate_tests 钩子 |
| --- | --- | --- |
| 测试文件要 import 吗 | 要 | 不要 |
| 用例名 ids 写在哪 | 测试文件里 | conftest 里，只写一次 |
| 多个测试文件复用 | 每个文件抄一遍 | 自动生效 |
| 稳定性 | 依赖 import 顺序 | 官方钩子，稳定 |

- E + where 200 = <Response [200]>.status_code 这行是 pytest写的

### 4.6 error 字段为什么该删

- error 字段是把信息压缩成"不能行动"的程度。 删掉它，让异常原样抛 —— 这是"测试要暴露问题"的直接体现。

### 5.3 sys.exit 被谁替代（退出码表）

- pytest 已经按"有没有失败"给了正确的退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部通过（含 xfail / skipped） |
| 1 | 有用例失败 |
| 2 | 测试执行被用户中断 |
| 3 | 内部错误 |
| 4 | 命令行用法错误 / conftest 加载失败 |

### 5.4 退出码 5 的坑

- 用例全被 -k 过滤掉、或者 CSV 读空了，退出码是 5 不是 0。
- xfail 和 skip 是 0。CI 上 "0 才算过" 这个判断，要确认没把 5 混进来。
