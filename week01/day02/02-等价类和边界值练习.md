# Day 2 等价类和边界类练习

- **日期**：2026-10-20
## 六个自检问题

1. **等价类划分和边界值分析，分别解决什么问题？为什么要配合使用？**

| 对比项 | 等价类划分 | 边界值分析 |
| --- | --- | --- |
| 核心目标 | 减少用例，覆盖不同输入类 | 重点发现边界附近缺陷 |
| 关注点 | 类内部代表值 | 边界及边界附近点 |
| 输入选择 | 每个等价类选代表值 | 取上点、离点、内点 |
| 主要解决 | 不能穷举、覆盖不系统 | 临界判断、差一、越界、极限值 |
| 单独使用局限 | 可能只测中间值，漏边界 | 只关注边界，不能覆盖类内部；依赖边界和有效域已知 |

- 原因一：等价类划分保证“面”

    边界值分析加强“线”。等价类划分把输入域分成若干“面”，每类取代表值；边界值分析在有效域和无效域的交界“线”上重点取值。
前者防止漏掉某类输入，后者防止漏掉边界缺陷。
- 原因二：等价类划分可能选不到边界

    例如年龄范围 [1,100]，如果等价类只取 50，就测不到 1、100、0、101 的处理。边界值分析正好补充这些关键点。
- 原因三：边界值分析需要等价类提供有效域

    边界值分析要知道哪里是边界、哪边有效、哪边无效，而等价类划分和需求分析正好帮助确定有效域与无效域。所以常见顺序是：先划分等价类，再对每个等价类的边界做边界值分析。
- 原因四：两者结合能用较少用例获得较高缺陷发现率

    有效等价类：选代表值，必要时组合覆盖；

    无效等价类：逐个隔离覆盖；

    对数值范围、长度、日期、容量等边界：补充上点、离点、内点。

    这样既避免穷举，又重点覆盖高风险边界。

2. **为什么有效等价类可以"一次盖多个"，无效等价类只能"一次盖一个"**

- 有效类组合后程序应继续走正常主路径，所以可以合并覆盖；无效类组合后程序常走“遇错即停”的异常路径，多个错误会互相遮蔽，所以通常一次只放一个无效输入，以保证每个异常规则都被独立触发和验证。

3. **范围 [1, 120]，要测哪几个边界值？为什么不能只测 1 和 120？**

- 要测0，121，1，120，60五个边界值。只测1和120只能证明在输入规则内是否有缺陷，不能证明在输入规则外没缺陷。

4. **"年龄 1–120 的整数"，你能拆出几个无效等价类？（提示：至少 5 个）**

- 可以拆出负数，小数，字符，0，121，空值，空格，7个无效等价类

5. **一个"密码 8–20 位、必须含大写字母和数字"的输入框，你会怎么划分等价类？**

- 有效等价类：

     1. a1：8 ≤ 长度 ≤ 20
     2. a2：至少包含一个大写字母
     3. a3：至少包含一个数字

- 无效等价类：

    1. b1：长度 < 8
    2. b2：长度 > 20
    3. b3：不含大写字母
    4. b4：不含数字

6. **边界值只测上下点、不测离点，会漏掉什么类型的缺陷？**

    1. **差一错误**
      - 范围 [1,100]程序误写成 x >= 0 && x <= 100，会错误接受 0
    2. **比较运算符等号方向写错，且错误只在外侧暴露**
      - 闭区间 [1,100] 被实现成 x >= 0 && x <= 100，会接受 0。
    3. **开闭区间实现错误**
      - 开区间 (1,100)若实现误写成 x > 2 && x < 100，会错误拒绝 2
    4. **循环、数组、字符串的相邻越界问题**
      - 数组长度 100，只测下标 0 和 99，不测 -1、100，可能漏掉越界访问
    5. **无效等价类在边界附近没有被覆盖**
      - 只测上点，等于没有验证“刚好超出有效范围一点点”时程序是否正确拒绝。
    6. **状态切换的“刚好超过”问题**
      - 余额 >= 0 允许交易，只测余额 0，不测余额 -1，可能漏掉负余额仍被允许的缺陷。
