# 2026-11-21 ｜ 同一条断言，三种写法

题面见 `练习/README.md` 的「11/21」一节。对象是 Postman 集合里的 `02-测试 GET 带 token`。

## 五段脚本（Postman → `02-测试 GET 带 token` → Scripts → After response）

前两条是原有的，后三条是今天加的（同一个断言三种写法）。

```js
pm.test("状态码是 200", function () {
    pm.response.to.have.status(200);
});

pm.test("服务器返回了 token", function () {
    pm.expect(pm.response.json().token).to.be.a('string').and.not.empty;
});

// ① 直接比较
pm.test("① expect: authenticated 为 true", function () {
    const body = pm.response.json();
    pm.expect(body.authenticated).to.eql(true);
});

// ② 只看某个字段的值
pm.test("② jsonBody: 字段值匹配", function () {
    pm.response.to.have.jsonBody("authenticated", true);
});

// ③ 校验整个结构（字段在不在 + 类型对不对）
pm.test("③ schema: 结构符合", function () {
    pm.response.to.have.jsonSchema({
        type: "object",
        required: ["authenticated", "token"],
        properties: {
            authenticated: { type: "boolean" },
            token: { type: "string" }
        }
    });
});
```

## 结果

```
5/5 PASSED
- 状态码是 200
- 服务器返回了 token
- ① expect: authenticated 为 true
- ② jsonBody: 字段值匹配
- ③ schema: 结构符合
```

响应体（`200 OK`）：

```json
{
  "authenticated": true,
  "token": "test-token-123"
}
```

## 卡点（三个）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **缺逗号** | `SyntaxError: Unexpected identifier 'token'`，Postman 显示 `Couldn't evaluate the test script`，**一条断言都没跑** | 每个属性写完就加逗号（先加后删）；报错指 `token`，问题在**上一行末尾** |
| **`true` 和 `"true"` 分不清** | `console.log` 打印出来**一模一样** | 用 `typeof`：`boolean` 写 `true`，`string` 写 `"true"` |
| **schema 只写了一个字段** | 另一个字段类型错了也不报警 | `required` 和 `properties` 都要把字段列全；schema 只校验**写进去的**字段 |

## 三条记住的

1. **`properties` ≠ 必须有** —— 它只管"有的话要符合"，"必须有"靠 `required`。实测：只有 `properties` 时 `{}` 也能通过。
2. **schema 管形状，`expect` 管值** —— schema 保证不了"值是 `true`"（`false` 也是合法布尔），`expect` 保证不了"字段没少"，两个经常要一起用。
3. **这类语法错是"脚本没执行"，不是"断言失败"** —— 看到 `Couldn't evaluate the test script`，先查语法（逗号/括号），别去查断言逻辑。

## 为什么同一个断言要会三种写法

| 写法 | 什么时候用 | 缺点 |
|---|---|---|
| `pm.expect` | 要**精确控制**错误信息、要比大小/包含 | 字段多就啰嗦 |
| `have.jsonBody` | 只看"某个字段等于某个值"，最快 | 只看一个字段 |
| `have.jsonSchema` | 校验**整个结构**（字段类型、必填、多余字段） | 失败时只报"整体不符合" |

**组合用法**：**schema 管结构 + 关键字段单独 `expect`**，两个一起用最稳。
